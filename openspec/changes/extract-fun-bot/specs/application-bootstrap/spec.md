# Spec Delta

## Purpose

Определяет, как независимый Fun-бот собирается в собственный исполняемый артефакт, регистрируется в Telegram, получает конфигурацию и завершается по SIGTERM, не оставляя висящую сессию long polling.

## ADDED Requirements

### Requirement: Собственный исполняемый артефакт

Система SHALL собираться командой `mvn clean package` на JDK 17 в один исполняемый jar `target/fun-telegram-bot-1.0.jar`, запускаемый через `java -jar` без дополнительного classpath и внешних файлов сборки. Приложение MUST NOT поднимать HTTP-сервер.

#### Scenario: Сборка с нуля

- **WHEN** выполняется `mvn clean package` на JDK 17 в чистом рабочем каталоге
- **THEN** создаётся `target/fun-telegram-bot-1.0.jar` со всеми runtime-зависимостями

#### Scenario: Запуск без веб-порта

- **WHEN** приложение запускается с корректными переменными окружения
- **THEN** оно регистрирует бота в Telegram и не открывает ни одного HTTP-порта

### Requirement: Регистрация бота с повторными попытками

Система SHALL пытаться зарегистрировать бота в Telegram не более трёх раз, логируя номер каждой попытки, и MUST завершаться с ненулевым кодом, если все попытки неуспешны.

#### Scenario: Успешная регистрация не с первой попытки

- **WHEN** первые попытки регистрации завершаются ошибкой, а одна из последующих успешна
- **THEN** в лог попадает сообщение об успешном запуске с номером попытки, и бот начинает обработку сообщений

#### Scenario: Все попытки неуспешны

- **WHEN** все три попытки регистрации завершились ошибкой
- **THEN** процесс завершается с ненулевым кодом, а перезапуск остаётся задачей systemd

### Requirement: Конфигурация из переменных окружения

Система SHALL получать `BOT_TOKEN`, `BOT_DB_URL`, `BOT_DB_USER`, `BOT_DB_PASSWORD` и `BOT_OWNER_CHAT_ID` из переменных окружения и MUST NOT требовать файл конфигурации или позиционные аргументы командной строки. Путь к картинкам SHALL задаваться `FUN_RESOURCES_PATH`, а прокси — переменными `BOT_PROXY_*`.

#### Scenario: Полный набор переменных

- **WHEN** приложение запускается с токеном, реквизитами базы и `BOT_OWNER_CHAT_ID`
- **THEN** бот запускается, а уведомление о запуске уходит указанному получателю

#### Scenario: Отсутствует обязательная переменная

- **WHEN** не задана одна из переменных `BOT_TOKEN`, `BOT_DB_URL`, `BOT_DB_USER`, `BOT_DB_PASSWORD`
- **THEN** приложение завершается с ненулевым кодом и сообщением с именем переменной, не подключаясь к базе и Telegram

#### Scenario: Получатель уведомления не задан

- **WHEN** `BOT_OWNER_CHAT_ID` пуст или содержит не число
- **THEN** бот запускается, уведомление не отправляется, в лог пишется предупреждение

#### Scenario: Прокси не задан

- **WHEN** `BOT_PROXY_HOST` пуст
- **THEN** бот подключается к Telegram API напрямую, в том числе через системный VPN

### Requirement: Корректная остановка по SIGTERM

Система SHALL прекращать long polling при получении SIGTERM и MUST завершаться в пределах `TimeoutStopSec=20` своего юнита, чтобы следующий запуск не конфликтовал с предыдущей сессией.

#### Scenario: Перезапуск юнита

- **WHEN** выполняется `systemctl restart fun-telegram-bot`
- **THEN** предыдущий процесс останавливает опрос обновлений, а новый регистрируется без ошибки конфликта сессии

#### Scenario: Остановка при активном опросе

- **WHEN** SIGTERM приходит, пока бот ожидает обновления от Telegram
- **THEN** опрос прекращается без ожидания таймаута, и процесс завершается штатно
